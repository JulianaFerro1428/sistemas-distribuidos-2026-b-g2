# Buenas prácticas de Scrum y Kanban

## Descripción

Este documento presenta los fundamentos y las principales buenas prácticas de **Scrum** y **Kanban**, metodologías utilizadas para la gestión y desarrollo de proyectos, especialmente en entornos de desarrollo de software.

El objetivo es comprender las características de cada metodología, sus elementos principales y las prácticas que permiten mejorar la organización, planificación, colaboración y flujo de trabajo de los equipos.

## Objetivos

* Comprender los fundamentos de Scrum y Kanban.
* Identificar las principales características de cada metodología.
* Reconocer los roles, eventos y artefactos utilizados en Scrum.
* Comprender los principios y prácticas fundamentales de Kanban.
* Comparar Scrum y Kanban según su forma de trabajo.
* Identificar buenas prácticas aplicables a proyectos de desarrollo de software.

## Scrum

Scrum es un marco de trabajo ágil que organiza el desarrollo mediante ciclos de trabajo llamados **Sprints**. Cada Sprint busca generar un incremento del producto que aporte valor.

### Elementos principales

| Elemento        | Descripción                                                                                         |
| --------------- | --------------------------------------------------------------------------------------------------- |
| Product Owner   | Responsable de maximizar el valor del producto y gestionar el Product Backlog.                      |
| Scrum Master    | Facilita Scrum, elimina impedimentos y ayuda al equipo a aplicar correctamente el marco de trabajo. |
| Developers      | Equipo encargado de desarrollar el incremento del producto.                                         |
| Product Backlog | Lista priorizada de necesidades, funcionalidades y mejoras del producto.                            |
| Sprint Backlog  | Elementos seleccionados del Product Backlog que se trabajarán durante el Sprint.                    |
| Incremento      | Resultado de trabajo terminado que cumple con la Definition of Done.                                |

### Eventos principales

* **Sprint:** período de tiempo en el que se desarrolla un incremento.
* **Sprint Planning:** planificación del trabajo del Sprint.
* **Daily Scrum:** reunión breve para inspeccionar el progreso y ajustar el trabajo.
* **Sprint Review:** revisión del incremento y recopilación de retroalimentación.
* **Sprint Retrospective:** análisis del proceso para identificar mejoras.

### Buenas prácticas de Scrum

1. Mantener el Product Backlog priorizado y actualizado.
2. Definir un objetivo claro para cada Sprint.
3. Mantener las reuniones enfocadas y con una duración adecuada.
4. Evitar introducir cambios que comprometan el objetivo del Sprint.
5. Mantener una comunicación constante entre los integrantes.
6. Establecer claramente cuándo una tarea se considera terminada.
7. Utilizar la retrospectiva para implementar mejoras reales.
8. Revisar periódicamente las prioridades del producto.

## Kanban

Kanban es un método de gestión visual que busca optimizar el **flujo de trabajo**, haciendo visible el estado de las tareas y limitando la cantidad de trabajo en progreso.

### Elementos principales

| Elemento       | Descripción                                                       |
| -------------- | ----------------------------------------------------------------- |
| Tablero Kanban | Representa visualmente el flujo de trabajo.                       |
| Columnas       | Representan los diferentes estados de una tarea.                  |
| Tarjetas       | Representan las tareas o elementos de trabajo.                    |
| WIP            | Límite de elementos que pueden estar en progreso simultáneamente. |
| Flujo          | Movimiento de las tareas desde el inicio hasta su finalización.   |

### Buenas prácticas de Kanban

1. Visualizar todo el trabajo en un tablero.
2. Dividir las tareas en unidades pequeñas y manejables.
3. Establecer límites de WIP.
4. Identificar y resolver rápidamente los bloqueos.
5. Evitar iniciar nuevas tareas cuando existe exceso de trabajo en progreso.
6. Medir el flujo de trabajo para identificar problemas.
7. Buscar mejoras continuas en el proceso.
8. Mantener las políticas de trabajo claras para todo el equipo.

## Comparación entre Scrum y Kanban

| Característica   | Scrum                                              | Kanban                                                 |
| ---------------- | -------------------------------------------------- | ------------------------------------------------------ |
| Tipo             | Marco de trabajo ágil                              | Método de gestión del flujo                            |
| Forma de trabajo | Sprints                                            | Flujo continuo                                         |
| Planificación    | Al inicio de cada Sprint                           | Continua                                               |
| Roles            | Product Owner, Scrum Master y Developers           | No requiere roles específicos                          |
| Reuniones        | Eventos definidos                                  | No establece eventos obligatorios                      |
| Tablero          | Puede reiniciarse o actualizarse por Sprint        | Flujo continuo de tareas                               |
| WIP              | Puede controlarse, pero no es obligatorio          | Es una práctica fundamental                            |
| Cambios          | Se recomienda proteger el objetivo del Sprint      | Los cambios pueden incorporarse continuamente          |
| Entrega          | Incrementos durante los Sprints                    | Entrega continua                                       |
| Métrica común    | Velocidad                                          | Lead Time, Cycle Time y Throughput                     |
| Adaptabilidad    | Alta, pero dentro del Sprint                       | Muy alta                                               |
| Mejor aplicación | Proyectos con objetivos y entregas por iteraciones | Procesos con trabajo continuo y prioridades cambiantes |

## Scrum y Kanban en conjunto

Scrum y Kanban no son necesariamente excluyentes. Algunas organizaciones utilizan prácticas de ambas metodologías para aprovechar sus ventajas.

Por ejemplo, un equipo puede utilizar:

* Sprints y retrospectivas de Scrum.
* Tablero visual de Kanban.
* Límites WIP.
* Métricas de flujo.
* Priorización del Product Backlog.

Esta combinación debe adaptarse a las necesidades reales del equipo y evitar implementar prácticas únicamente por cumplir con una metodología.

## Buenas prácticas generales

Independientemente de la metodología utilizada, se recomienda:

* Mantener las tareas claramente definidas.
* Priorizar el trabajo según el valor que aporta.
* Mantener una comunicación constante.
* Reducir el trabajo innecesario.
* Identificar bloqueos oportunamente.
* Medir el desempeño del proceso.
* Revisar periódicamente la forma de trabajo.
* Promover la mejora continua.
* Mantener transparencia sobre el estado del proyecto.

## Conclusión

Scrum y Kanban proporcionan diferentes enfoques para gestionar proyectos y equipos de trabajo.

**Scrum** se enfoca en trabajar mediante iteraciones estructuradas, mientras que **Kanban** se centra en optimizar el flujo continuo de trabajo.

La elección de uno u otro debe depender de las características del proyecto, la estructura del equipo y la naturaleza del trabajo. En ambos casos, el objetivo principal debe ser mejorar continuamente el proceso y entregar valor de manera eficiente.
